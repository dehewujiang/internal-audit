# 2026-07-26 工作日志

## 证据集中存储与智能匹配改造

### 背景
当前证据按程序文件夹存放，一份文件被多个程序引用时需复制多份。客户要求解决文件复用问题。

### 方案设计
经过多轮讨论确定最终方案：
- 证据文件集中存放于 `_files/` 目录
- 证据清单 `_evidence_catalog.json` 由 Python 从程序 Markdown 的"取证方式"列自动生成
- 槽位分"已收集"和"缺失"两种状态，用户能看到完整进度
- 匹配策略：Python 结构指纹 → LLM 综合判断 → 用户确认
- OCR（PaddleOCR）不用于匹配阶段——实测 20分钟/8页，不实际

### 技术发现
- 审计程序 Markdown 六个轨道（A-F）均有"取证方式"列，可程序化提取
- PaddleOCR 已安装可运行，核心文本识别率 90%+，但速度慢
- 审计程序 v3.0 的列结构比 v1.0 多了"取证方式"列，向后兼容需处理

### 改动清单
1. `_shared/scripts/create_evidence_dirs.py` → 新增 catalog 生成 + _files/ 目录
2. `_shared/scripts/evidence_catalog.py` → 新建：catalog CRUD + 文件扫描 + 关键词匹配
3. `audit-execution-assistant/SKILL.md` → 更新证据路径 + 匹配流程
4. `constitution.md` → 更新证据路径描述
5. `finding_schema.md` → 更新 storage_path 示例

### 验证结果
- catalog 生成：用 人力资源管理_审计程序_v3.0.md 成功生成 162 个槽位，33 个多程序共享
- 文件扫描：成功提取 Excel 文件的列名和行数
- 匹配：基础关键词匹配可用，供 LLM 做最终判断
