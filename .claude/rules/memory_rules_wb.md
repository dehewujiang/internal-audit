# 跨项目记忆规则

## 1. 文件结构

所有记忆文件存放于项目根目录 `memory/`，命名统一小写（INDEX.md、TODO.md 除外）：

```
memory/
├── INDEX.md       # 索引（必须存在）
├── decisions.md   # 重要决策记录（为什么变成现在这样）
├── context.md     # 技术上下文压缩（供上下文压缩后快速恢复）
├── TODO.md        # 行动清单
├── project.md     # 项目状态——用户视角（唯一事实来源）
├── session.md     # 最近一次工作交接
├── user.md        # 用户长期偏好
├── feedback.md    # 经验教训
└── forks/         # 分叉任务
```

新项目初始化时用到的模板，见 memory-templates.md（平时不需要，只在新建项目或执行 geb-bootstrap 时才用）。

## 2. project.md 与 context.md 的职责切割

两个文件看起来相似，写给不同的读者，禁止把同一条信息重复写入两个文件：

| | project.md | context.md |
|:---|:---|:---|
| 写给谁 | 用户：我们做了什么，做到哪了 | AI：上下文压缩后快速恢复技术状态 |
| 使用语言 | 非技术口语 | 精确技术语言 |
| 更新时机 | 每次收工 | 收工时 + 上下文压缩前 |
| 记录内容 | 功能进度、风险、下一步、系统结构 | 核心模块关系、关键约束、技术决策摘要、活跃风险 |

## 3. 工具内置记忆与手动记忆的关系

部分 AI 编码工具内置自动记忆功能（如 Claude Code Auto Memory、WorkBuddy 每日日志），与本手动系统并行，不得混用：

| 系统 | 负责记录 | 维护方式 |
|:----|:--------|:--------|
| 工具内置记忆 | 技术细节、构建命令、操作日志 | AI 工具自动写入 |
| 手动 memory/ | 项目状态、用户偏好、决策记录 | 用户 + AI 共同维护 |

## 4. 什么值得写入手动记忆（三筛法）

同时满足以下三条才写入：

- **跨 session 有价值**：长期偏好、架构决策（非本次临时状态）
- **从代码读不出来**：为什么选 A 不选 B
- **三个月后还有用**："timeout 不能写死" ✓ / "今天改了拼写" ✗

## 5. 写入规则

### 直接写入（不询问）

| 触发 | 写入文件 |
|:----|:--------|
| 用户说"记下来/别忘了/存一下" | 按内容判断 |
| 用户纠正 AI 并说明理由 | `feedback.md` |
| 用户说"以后都这样/默认就这个" | `user.md` |
| 用户确认架构方向或技术选型 | `decisions.md` |

写入后立即更新 INDEX.md 索引。

### 满足三筛但不在上表 → 问"这个要不要存？"

连续三次被否决 → 该类不再问。

## 6. TODO.md 更新时机

| 触发 | 操作 |
|:----|:----|
| 用户提出新任务 | 加入 #进行中 |
| 用户确认完成 | 移到 #已完成，标注日期 |
| 用户说"先放一放" | 移到 #待办 或标注 #阻塞 |
| 发现新风险或阻塞 | 加入 #阻塞，标注原因 |
| 用户改变优先级 | 调整顺序 |

禁止推测：用户没明确表态的，不改状态。

## 7. Session 启动与结束协议

### 启动协议（完整读取，零遗漏）

每次对话开始，强制执行：

1. 读取以下 6 个文件（不分先后，全部必读）：
   1. `memory/project.md` — 项目现状
   2. `memory/TODO.md` — 当前任务与阻塞
   3. `memory/session.md` — 上次工作交接
   4. `memory/decisions.md` — 历史决策记录
   5. `memory/context.md` — 技术上下文
   6. `memory/feedback.md` — 踩坑记录与教训
2. 若 memory/ 目录不存在 → 执行新项目初始化：
   - 创建 memory/ 目录及 memory/forks/ 子目录
   - 按 memory-templates.md 的模板创建所有记忆文件
   - 向用户询问项目名称和目标，填入 memory/project.md
   - 告知用户记忆系统已就绪，可以开始工作。
3. 启动汇报（格式固定）：项目是什么 + 当前状态 / 接下来最重要的任务 / 当前最大风险 / 建议下一步。

**INDEX.md 不参与启动流程**——INDEX.md 仅在结束协议中维护。

### 结束协议

当用户说"收工/结束/今天到这里"时：

1. **强制检查**：自检本次是否有代码变更。
2. **条件阻断**：只有本次 session 触发了 project-doctrine.md〈architecture_documentation〉第二层（即本次会话出现了文件新增/删除/移动、模块重组、职责重新划分等架构级变更），才需要更新对应目录的 CLAUDE.md。如果本次全是日常改动，直接进入下一步。
3a. 更新 project.md / TODO.md / session.md / decisions.md / context.md / feedback.md。
3b. 上述任何文件有变动时，同步更新 INDEX.md（日期 + 摘要列）。
4. 告知：本次完成了什么 / 发现了什么 / 未完成的是什么 / 建议下一步 / 项目健康（✅/⚠️/🔴）。

## 8. 各文件职责

**project.md** — 用户视角的项目现状。必须回答：项目是什么 / 当前进度 / 已完成功能 / 正在做什么 / 最大风险 / 下一步 / 系统结构（非技术语言）。禁止写调试过程和代码细节。

**decisions.md** — 为什么变成现在这样。适用：架构选型 / 技术路线调整 / 放弃方案及原因。每条决策用 ADR 格式，顺序编号。

**context.md** — 技术上下文压缩。供对话上下文压缩后或新会话快速恢复。语言可精确技术化。

**session.md** — 工作交接。只保留最近一次，允许覆盖。记录：今天做了什么 / 为什么 / 遇到什么问题 / 下一步建议。

**user.md** — 长期有效、持续影响协作方式的信息。

**feedback.md** — 失败案例和根因 / 放弃的方案 + 放弃理由 / 下次同类工作要提前注意的事。

**INDEX.md** — 索引表：

| 文件 | 最后更新 | 摘要 |
|:----|:--------|:----|
| project.md | 日期 | 一句话说明 |

## 9. 文件优先级（冲突时以此为准）

```
代码/事实 > project.md > decisions.md > TODO.md > context.md > session.md
```

## 10. 上下文压缩保留指令

当对话上下文压缩触发时，必须保留：

- memory/ 目录下所有文件的最新内容摘要
- 当前进行中的任务和未完成事项
- 本次 session 已做的关键决策
- 用户明确说「不做」的事情

压缩后，系统会自动重新注入全局配置和项目规则。子目录 CLAUDE.md 和路径匹配规则需要等 AI 再次读取文件时才会重新加载——如果压缩后需要继续工作，建议先回读 `memory/` 文件确认状态一致。

## 11. 记忆防遗忘机制（弱一致读取）

### 写入强一致（不可违背）

踩坑后、做出重大架构决策后、用户明确纠正后，必须立即写入对应的 memory 文件，绝不依赖会话结束再补。

### 读取弱一致（灵活机动）

- 启动时已完整读取所有 6 个记忆文件（见启动协议），工作过程中不强制重复读取。
- 但在遇到以下情况时，必须主动重新检索 `memory/feedback.md` 和 `memory/decisions.md`：
  1. 遇到报错或代码卡壳，准备重构某个模块时。
  2. 用户说"继续上次的任务"或"按之前的方法做"时。

### 兜底确认

若因对话过长导致上下文模糊，且当前任务风险较高，宁可多嘴问一句："哥，这块逻辑我们之前踩过坑吗？"，也不要盲目猜测。
