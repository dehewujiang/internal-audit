# GEB 分形文档协议 v2（项目宪法）

代码是机器相，文档是语义相，两相必须同构。
The map IS the terrain.
这种同构思想源自《哥德尔、埃舍尔、巴赫》——不同系统间的结构性映射是可持续迭代的前提。

## 核心铁律

- 修改代码时文档在注视我，编写文档时代码在审判我。
- 三层分形：
  - L1 = /CLAUDE.md（全局地图：目录 / 配置 / 法则）
  - L2 = /{module}/CLAUDE.md（成员清单 + 父级链接）
  - L3 = 文件头部注释（INPUT / OUTPUT / POS）
- 文件对不变式：每个有文档的目录同时存在 CLAUDE.md + AGENTS.md(symlink)，保证不同 Agent 工具发现同一份文档。
- 制度大于个人，文档大于记忆，流程大于英雄。

<architecture_documentation>
两层检查，避免"日常改动被当成架构变更要求同步文档"和"真正的架构变更被漏掉"这两件事同时发生：

- **第一层·随手检查**（每次代码改动都做，成本接近零）：改完代码、准备说"改完了"之前，自问一句——这次改动有没有涉及文件新增/删除/移动、模块重组、职责重新划分？没有 → 直接汇报完成，不用碰 CLAUDE.md。
- **第二层·文档同步**（只有第一层判断"是"才做）：批处理统一更新对应目录的 CLAUDE.md，再汇报完成。

哲学意义：CLAUDE.md 是架构的镜像，不是变更日志。频繁震荡会失忆，定期对齐才清晰——但"要不要震荡"这个判断本身，每次都要做，不能省略。
</architecture_documentation>

<documentation_protocol>
同步内容：目录结构树形展示、架构决策及原因、模块职责边界。
格式要求：凝练如诗，精准如刀。每个文件用一句话说清本质，每个模块用一段话讲透设计。
操作流程：任务代码完成 → 做第一层随手检查 → 若判断为架构级变更则做第二层批处理更新 → 汇报用户。
核心原则：文档滞后是技术债务，但文档震荡是系统噪音。在任务边界统一清偿债务。
</documentation_protocol>

## 关键命令

- 文档同步检查：`/geb-workflow`
- 冷启动播种：`/geb-bootstrap`
- 查看已加载规则：`/memory`

## 规则路由（按路径自动加载）

编辑文件时，以下规则会按路径自动注入：

| 触发路径 | 加载规则 |
|---|---|
| `**/*.{py,js,ts,go,java,rs,html,css,jsx,tsx}` | `coding-safety.md` + `good-taste.md` + `geb-l3.md` |
| `**/api/**`, `**/interface/**`, `**/public/**` | 额外加载 `compat.md` |


## 规则冲突裁决

规则冲突时优先级：具体 rules 文件 > 本宪法 > /CLAUDE.md 事实层 > memory_rules.md > 全局 ~/.claude/CLAUDE.md。

同一优先级内部，如果两份 rules 文件直接冲突（例如 good-taste.md 主张"内部实现无需考虑兼容" vs compat.md 主张"绝不破坏用户空间"），这张表本身分不出胜负，按以下顺序单独裁决，不再靠某一份文件里的脚注单独兜底：

1. 涉及 `api/`、`interface/`、`public/` 目录的对外接口 → compat.md 赢，其他同级文件在这个范围内自动让位。
2. 不涉及对外接口的内部实现 → 按各文件本身的适用范围判断，无需援引 compat.md。
3. 仍无法判断谁该赢 → 停下来问用户，不擅自选一个。

## 边界条件（必须知道）

path-scoped rules 是在 Claude 读取匹配文件时注入，不是每次工具调用前都注入。
所以"L3 头部缺失即添加"这类新建文件硬约束，已写入本节核心铁律，rules 文件只负责编辑已有文件时的细则。

## 工作流强制拦截（不可绕过）

以下场景必须触发对应 Skill，禁止直接输出结果：

1. **代码变更后**：无论改动大小，在汇报"修改完成"之前，必须做完 architecture_documentation 的第一层随手检查——这一步很快，不增加明显成本。只有第一层判断为"架构级变更"时，才需要真正执行第二层的 CLAUDE.md 更新。如果 L3 头部与代码明显不一致（YELLOW 警告），必须在本次任务结束前清偿，不能拖到下次。
2. **新项目/空目录启动**：检测到 CLAUDE.md 缺失或 L3 头部大面积缺失时，必须先提示用户并调用 `/geb-bootstrap`，禁止在无文档骨架下直接写代码。

判断标准：如果你正在修改 `**/*.{py,js,ts,go...}` 等源码文件，且准备输出"修改已完成"，此时若没做完第一层检查，视为严重违规；第一层判断是架构级变更却没做第二层，同样视为严重违规。
