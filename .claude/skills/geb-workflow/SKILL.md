# GEB 回环检查工作流

## 正向流（代码 → 文档）

### STEP 1：L3 检查

对比文件头部 INPUT/OUTPUT/POS 与实际代码：
- GREEN：完全一致 → 通过
- YELLOW：轻微不符（参数名/类型）→ 立即修复，不阻断
- RED：严重不符（职责变更/依赖断裂）→ 必须修复后再继续

### STEP 2：L2 检查

检查同级 CLAUDE.md 的成员清单：
- 无文件增删 / 职责变 / 接口变 → 通过
- 有变化 → 更新成员清单，父级链接保持完整

### STEP 3：L1 检查

检查根 CLAUDE.md 的全局地图：
- 无模块增删 / 技术栈变 → 通过
- 有变化 → 更新全局地图，同步版本号

## 容错原则

- 紧急 hotfix：允许先修代码，24h 内补齐文档。
- 文档滞后是 YELLOW 不是 RED：警告但允许继续，任务结束前清偿。
- symlink 断裂：自动重建，不视为错误。
- 文档同步是理想不是枷锁：可逆错误可容忍，任务完成前必须清偿文档债务。

## 报告格式
L3: [GREEN/YELLOW/RED] - 详情
L2: [GREEN/YELLOW/RED] - 详情
L1: [GREEN/YELLOW/RED] - 详情
总评: [通过 / 需修复 / 阻断]
待清偿债务: [列表]
