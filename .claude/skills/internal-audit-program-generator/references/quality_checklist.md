# 质量自检清单

## Step 0-1

- [ ] 已读取 about-me.md 和 my-config.md（或完成降级询问）
- [ ] 审计主题已明确
- [ ] 审计目的已通过选择表单确认（非默认值）
- [ ] 触发原因已询问并确认
- [ ] 已展示信息确认摘要，用户确认无误
- [ ] 目的级联路由已完成，已确认激活的轨道

## Step 2 基础风险识别

- [ ] 每个风险点均已通过**事实锚定自检**（可指向 about-me.md / my-config.md / 制度分析JSON的具体行）
- [ ] 【经验类】每个风险点描述了在本公司场景下的具体表现形式（非通用行业描述）
- [ ] 【系统类】每个风险点引用了 my-config.md 中的具体系统名称和模块
- [ ] 【公司类】每个风险点在 about-me.md 中有 ≥2 条独立事实作为支撑依据
- [ ] 【制度类-设计缺陷】每个风险点引用了具体制度编号和条款内容
- [ ] 无仅靠数量最低值产出的填充型风险（已废弃"≥5个"规则）

## Step 2.2 目的自适应（按目的）

- [ ] 运营效率审计：【效率类】风险已基于公司特征推演，数量和维度符合审计主题
- [ ] 合规性审计：【合规类】风险已基于公司实际客户/法规要求推演

## Step 2.5 跨类扫描

- [ ] 跨类复合风险已基于 Step 2 风险清单动态推演（非预设组合）
- [ ] ERP主数据风险已基于 my-config.md 中实际系统动态推演（非预设清单）
- [ ] 所有补充项均已标注【跨类-Step2.5】或【ERP主数据-Step2.5】

## Step 3 程序生成

### 轨道A（控制有效性测试）

- [ ] 所有风险均有控制有效性测试程序
- [ ] 如 Step 0.3 有输入，已包含所有 baseline_audit_program
- [ ] 所有系统名称来自 my-config.md，无通用描述
- [ ] 无"大额""高风险"等模糊词

### 轨道B（舞弊实质性测试）

- [ ] 仅【经验类】风险进入本轨道
- [ ] 【系统类】【公司类】【效率类】【合规类】未错误进入
- [ ] 程序为实质性测试（含量化阈值和取数系统）
- [ ] 无控制有效性测试程序（轨道B必须是实质性测试）

### 轨道C（系统/公司类实质性测试）

- [ ] 【系统类】【公司类】及 Step 2.5 风险均有实质性测试程序
- [ ] 所有程序包含具体系统名（来自 my-config.md）

### 轨道E（运营效率专项）

- [ ] 先自由生成，后读取 playbook 比对
- [ ] 新程序已提示归档（不自动写入）
- [ ] 效率损失金额已基于 about-me.md 数据具体估算（无 _X_ 占位符）
- [ ] 每个效率损失估算标注了置信度（高/中/低）
- [ ] 无双轨内容混入（无舞弊取证类程序）

### 轨道F（合规专项）

- [ ] 先自由生成，后读取 playbook 比对
- [ ] 新程序已提示归档（不自动写入）
- [ ] 区分"有制度未执行"和"有操作无制度"

### 轨道D（边界探测）

- [ ] 已完成边界探测（除非时间明确受限）
- [ ] 最多2个风险点（宁缺毋滥）
- [ ] 每个风险点通过了"是否这家公司独有"检验（附具体原因）
- [ ] 无通用型风险（如AI生成虚假单据、数字化供应链舞弊等）
- [ ] 风险点解释中引用了 about-me.md 或 my-config.md 的具体公司特征

## 输出格式

- [ ] 未激活的轨道章节已标注"已跳过"而非留空
- [ ] 轨道E/F中的 playbook 补充内容均已标注【playbook补充】
- [ ] 输出中无会计报表审计内容（无存货跌价、截止测试、会计估计）

## 质量评估

- [ ] 已调用 `internal-audit-evaluator`
- [ ] 评估报告已完整附加在输出末尾（未裁剪）
- [ ] 如评分低于阈值，已提示重新生成

### 推理链回溯（新增）

- [ ] 已完成前3个高风险风险点的推理链回溯
- [ ] 所有回溯点的 ✅ 数量 ≥ 3 个（无 🔴 质量待审标记）
- [ ] 如有 ❌，已在文档末尾附加 ⚠️ 或 🔴 标记

## 上下文管理

- [ ] references/ 文件作为背景知识，未全文输入
- [ ] 制度分析 JSON 如超过5个文件，仅读取关键字段
- [ ] 生成的审计程序未超过300行（或已拆分）
