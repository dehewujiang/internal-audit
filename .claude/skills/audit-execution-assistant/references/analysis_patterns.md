# 数据分析模式

## 概述

本文档定义了审计执行中常用的数据分析模式，用于audit-execution-assistant在分析证据时参考。

## 使用方式——先元方法，后模式

**重要顺序**：在执行任何下述分析模式之前，必须先在 Step 2.4 中完成"证据分析框架自生成"（四问框架），然后用自生成的检查清单来决定调用哪些模式。

**关系**：

```
证据文件 → Step 2.4 四问框架 → 自生成检查清单
                                    ↓
                    对清单中的每项检查，匹配适合的模式：
                    ├─ 金额比对 → 模式1（金额阈值分析）
                    ├─ 职责检查 → 模式2（职责分离分析）
                    ├─ 跨期检查 → 模式3（趋势分析）
                    ├─ 价格检查 → 模式4（价格比对分析）
                    ├─ 记录检查 → 模式5（完整性分析）
                    ├─ 系统对账 → 模式6（跨系统数据比对）
                    ├─ 离群检测 → 模式7（异常值检测）
                    └─ 无模式匹配 → LLM自行推理执行，禁止跳过
```

**禁止行为**：
- ❌ 不经过四问框架直接调用模式 → 可能导致分析目标偏移
- ❌ 检查清单中的项无模式匹配就跳过 → 应 LLM 自行推理
- ❌ 将四问框架替换为"匹配最近的场景" → 违背元方法设计意图

## 分析模式库

### 模式1：金额阈值分析

**适用场景**：测试审批权限控制

**分析逻辑**：
1. 筛选超过阈值的记录
2. 检查每条记录的审批人是否符合制度要求
3. 计算异常比例

**异常判定**：
- 审批人层级低于制度要求 → 异常
- 审批时间在业务发生之后 → 异常
- 无审批记录 → 异常

### 模式2：职责分离分析

**适用场景**：测试不相容职责是否分离

**分析逻辑**：
1. 提取业务记录中的执行人信息
2. 比对同一人在不同环节的执行记录
3. 识别兼任情况

**异常判定**：
- 同一人执行了不相容环节 → 异常
- 兼任频率超过阈值 → 异常

### 模式3：趋势分析

**适用场景**：测试定期检查控制

**分析逻辑**：
1. 按时间维度汇总检查记录
2. 检查是否按制度要求的频率执行
3. 识别缺失的检查周期

**异常判定**：
- 应每月执行但实际有缺失月份 → 异常
- 检查间隔超过制度要求 → 异常

### 模式4：价格比对分析

**适用场景**：测试采购价格合理性

**分析逻辑**：
1. 提取采购价格数据
2. 与市场价/历史价/同类供应商价格比对
3. 计算偏差率

**异常判定**：
- 价格高于市场价X% → 异常
- 同一物料不同供应商价格差异超过X% → 异常
- 价格持续上涨但无合理解释 → 异常

### 模式5：完整性分析

**适用场景**：测试文档记录控制

**分析逻辑**：
1. 检查记录要素是否完整
2. 识别缺失必填字段的记录
3. 计算完整率

**异常判定**：
- 必填字段缺失率超过X% → 异常
- 关键字段（金额、日期、审批人）缺失 → 异常

### 模式6：跨系统数据比对

**适用场景**：测试系统间数据一致性

**分析逻辑**：
1. 从两个系统提取同一业务的数据
2. 比对关键字段
3. 识别不一致记录

**异常判定**：
- 同一业务在两个系统中金额不一致 → 异常
- 同一业务在两个系统中状态不一致 → 异常

### 模式7：异常值检测

**适用场景**：识别数据中的异常模式

**分析方法**：
- 统计分布分析：识别超出3σ的值
- 时间序列分析：识别异常波动
- 关联分析：识别异常关联（如同一IP地址的多个供应商）
