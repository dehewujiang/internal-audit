# Finding判定规则

## 概述

本文档定义了审计执行中判定是否生成Finding的规则，确保finding的质量和一致性。

## 判定流程

```
发现异常
    ↓
证据完整性校验
    ↓ 通过
重要性水平判断
    ↓ 超过阈值
风险级别判定
    ↓
中国审计现实判断框架
    ↓
生成Finding
```

## 中国审计现实判断框架（必读）

在判断是否将问题写成正式审计发现时，不能仅依据法规是否违反。必须同时评估以下三个维度：

| 维度 | 问题 | 判断标准 |
|------|------|----------|
| 爆发后果 | 如果被监管部门查到或被媒体曝光，对公司影响有多大？ | 后果严重（刑事责任、重大罚款、声誉崩塌）→ 倾向写；后果轻微（小额罚款、行业普遍）→ 倾向不写 |
| 老板知情 | 老板是否已经知道这个问题，但选择不管？ | 老板知情且默许 → 倾向不写；老板不知情 → 倾向写 |
| 行业普遍性 | 这个问题在行业内是否常见？ | 行业普遍 → 倾向不写；行业罕见 → 倾向写 |

**决策规则**：
- 三个维度都指向"风险可控"：私下沟通，不写正式发现
- 任一维度指向"风险严重"：写成正式发现，但措辞要务实，聚焦业务后果而非法律条文
- 两个以上维度指向"风险严重"：必须写成正式发现，且风险定级为高

**典型场景**：
- 劳务派遣比例超标（行业普遍、老板知情、罚款轻微）→ 私下与HR沟通，不写正式发现
- 关联交易利益输送（价格明显高于市场价）→ 写成正式发现，因爆发后果严重（可能涉及刑事责任）

**重要提醒**：审计的目标是保护公司，不是当合规警察。在中国民企里，"有用"比"正确"更重要。

## 证据完整性校验

### 校验矩阵

| 校验项 | 充分 | 部分充分 | 不足 |
|--------|------|---------|------|
| 覆盖度 | 覆盖所有测试要素 | 覆盖主要测试要素 | 仅覆盖部分测试要素 |
| 时间范围 | 完全匹配审计期间 | 覆盖主要期间 | 期间不完整 |
| 样本量 | 达到最低要求 | 接近最低要求 | 远低于最低要求 |
| 来源可靠性 | A级证据 | B/C级证据 | D/E级证据 |
| 一致性 | 多来源相互印证 | 基本一致，有小矛盾 | 存在重大矛盾 |

### 处理规则

| 证据完整性 | 异常确认度 | 处理方式 |
|-----------|-----------|---------|
| 充分 | 确认 | 生成Finding，正常风险级别 |
| 充分 | 疑似 | 生成Finding，标注"疑似" |
| 部分充分 | 确认 | 生成Finding，标注"证据部分充分" |
| 部分充分 | 疑似 | 标记"待确认"，不生成Finding |
| 不足 | 任何 | 标记"需要补充证据"，不生成Finding |

## 重要性水平判断

### 财务重要性

| 金额区间 | 处理方式 |
|---------|---------|
| ≥ 50万元 | 高风险Finding |
| 5-50万元 | 中风险Finding |
| < 5万元 | 低风险Finding或观察事项 |

### 非财务重要性

| 影响类型 | 处理方式 |
|---------|---------|
| 合规违规 | 高风险Finding |
| 内控缺陷（系统性） | 中风险Finding |
| 内控缺陷（偶发性） | 低风险Finding |
| 效率问题 | 观察事项 |

### 舞弊特殊规则

**舞弊零容忍原则**：
- 任何舞弊嫌疑，无论金额大小，均标记为高风险Finding
- 红旗信号（如关联交易未披露、虚假单据）直接生成Finding

## 风险级别判定标准

### 高风险

| 条件 | 示例 |
|------|------|
| 涉及舞弊嫌疑 | 虚假发票、串通投标 |
| 金额 ≥ 50万元 | 大额采购未审批 |
| 系统性内控失效 | 整个审批流程被绕过 |
| 合规违规 | 违反法律法规 |
| 可能引发监管处罚 | 环保违规、税务违法 |

### 中风险

| 条件 | 示例 |
|------|------|
| 金额 5-50万元 | 中等金额采购未审批 |
| 偶发性内控缺陷 | 个别单据缺少审批 |
| 制度设计缺陷 | 制度中缺少关键控制 |
| 效率损失明显 | 重复工作导致成本增加 |

### 低风险

| 条件 | 示例 |
|------|------|
| 金额 < 5万元 | 小额费用报销缺少附件 |
| 轻微内控缺陷 | 个别记录不完整 |
| 操作不规范 | 未按流程填写表单 |

### 观察事项

| 条件 | 示例 |
|------|------|
| 不构成缺陷但有改善空间 | 流程可以优化 |
| 效率提升机会 | 自动化可以替代手工操作 |
| 预防性建议 | 建议增加某项控制 |

## Finding标题规范

标题格式：`[数量] + [对象] + [问题] + [影响]`

示例：
- ✅ "3笔大额采购未经总经理审批，涉及金额18.5万元"
- ✅ "存货盘点差异率3.2%，超过1%的重要性水平"
- ❌ "采购审批问题"（太模糊）
- ❌ "发现一些异常情况"（不具体）

## 关联规则

### 与Control Point关联

每个Finding应关联到相关的控制点ID：
- 控制测试类Finding → 关联到被测试的CP
- 实质性测试类Finding → 关联到相关的CP或CG

### 与Audit Program关联

每个Finding应关联到发现该异常的审计程序：
- 格式：`程序N：[程序名称]`

### 跨Finding关联

如果多个Finding涉及同一根因，应在description中注明关联：
- "本发现与F-2026-002涉及同一根因：ERP系统权限配置不当"
