# 文档分析指导

## 概述

本指南说明如何分析企业内部制度文档，提取关键信息并转化为具体的内部审计程序。

---

## 文档类型

### 常见企业制度文档

| 文档类型 | 内容 | 用途 |
|----------|------|------|
| **管理制度** | 某业务领域的管理规定 | 识别控制点和要求 |
| **流程文件** | 业务流程描述和流程图 | 识别流程节点和风险 |
| **操作手册** | 具体操作说明 | 了解实际执行方法 |
| **岗位职责** | 部门和岗位的职责分工 | 识别职责分离情况 |
| **表单模板** | 各类审批单、记录表 | 了解信息记录要求 |
| **内控手册** | 内部控制手册 | 了解内部控制框架 |

---

## 如何从企业制度中提取控制点

### 控制点类型

控制点是制度中规定的关键控制措施，常见类型包括：

#### 1. 审批权限控制

**识别方法**：搜索关键词"审批"、"批准"、"签字"

**示例**：
```
制度原文："采购金额5万元以上需总经理审批"
提取的控制点：
- 控制类型：采购审批控制
- 审批权限：5万元以上总经理审批
- 审批方式：书面签字或系统审批
```

**转化为审计程序**：
- 抽取金额>5万元的采购
- 检查是否有总经理签字/系统审批记录
- 检查审批时间是否在采购之前

#### 2. 职责分离控制

**识别方法**：搜索"职责分离"、"不相容"、"分别"

**示例**：
```
制度原文："采购申请人与验收人应为不同人员"
提取的控制点：
- 控制类型：职责分离控制
- 分离要求：申请和验收职责分离
```

**转化为审计程序**：
- 获取采购申请单和验收单
- 比对申请人和验收人
- 识别同一人员兼任的情况

#### 3. 定期检查控制

**识别方法**：搜索"定期"、"每月"、"每季度"、"每年"

**示例**：
```
制度原文："每月对仓库进行盘点"
提取的控制点：
- 控制类型：定期盘点控制
- 检查频率：每月一次
- 检查对象：仓库存货
```

**转化为审计程序**：
- 获取最近6个月的盘点报告
- 检查盘点是否按月执行
- 分析盘点差异和处理情况

#### 4. 文档记录控制

**识别方法**：搜索"记录"、"登记"、"台账"

**示例**：
```
制度原文："所有出入库必须登记台账"
提取的控制点：
- 控制类型：文档记录控制
- 记录要求：出入库台账
```

**转化为审计程序**：
- 检查台账是否完整记录
- 核对台账与实物

## 如何识别制度中的风险点

### 风险点类型

#### 1. 流程断裂点

**定义**：流程中缺少必要环节或环节衔接不当。

**识别方法**：
- 分析流程图中的断点
- 识别缺少的环节（如：审批后无验收）
- 识别环节顺序不合理

**示例**：
```
流程：采购申请 → 审批 → 付款
风险点：缺少"验收"环节，可能虚假采购
```

#### 2. 权限集中点

**定义**：某人或某岗位权力过大，缺乏制衡。

**识别方法**：
- 查找"全权负责"、"一人审批"
- 分析岗位职责描述
- 识别一人兼任多个不相容岗位

**示例**：
```
制度原文："采购员负责询价、下单、验收"
风险点：采购员权力集中，容易舞弊
```

#### 3. 监督盲区

**定义**：某些活动缺乏监督或检查。

**识别方法**：
- 查找缺少"检查"、"监督"、"复核"的环节
- 识别无人负责的活动
- 识别长期未检查的活动

**示例**：
```
制度原文："废料处置由仓库负责"
风险点：缺少监督，废料处置收入可能被侵占
```

#### 4. 信息不对称点

**定义**：某些信息只有特定人员掌握，缺乏透明度。

**识别方法**：
- 查找"仅某人知晓"、"保密"等描述
- 识别缺乏共享的信息
- 识别缺乏对账的信息

**示例**：
```
制度原文："供应商定价由采购部确定"
风险点：定价信息不透明，可能虚高
```

## 如何将制度要求转化为审计程序

### 转化步骤

#### Step 1: 提取制度要求

**方法**：
1. 阅读、精读制度文档
2. 标注关键要求
3. 整理成控制点清单

**示例**：
```
制度要求：
1. 采购金额>5万需总经理审批
2. 每月进行仓库盘点
3. 采购员与验收员职责分离
4. 所有出入库必须登记台账
```

#### Step 2: 确定审计目标

**方法**：基于控制点确定审计目标

**示例**：
```
控制点1: 采购审批制度
→ 审计目标：验证大额采购是否经过适当审批
```

#### Step 3: 设计审计程序

**程序要素**：
- **测试方法**：控制测试还是实质性测试
- **样本选择**：抽取多少样本
- **证据来源**：从哪里获取证据
- **判断标准**：如何判断是否通过

**示例**：
```
控制点: 采购金额>5万需总经理审批
审计程序：
1. 测试方法：控制测试
2. 样本选择：抽取25笔金额>5万的采购
3. 证据来源：ERP系统审批记录
4. 判断标准：是否有总经理审批记录
```

## 汽车零部件企业制度分析要点

### 采购管理制度分析

**关注要点**：

| 要点 | 分析内容 | 转化为程序 |
|------|----------|------------|
| **审批权限** | 各金额级别的审批人 | 抽样检查审批记录 |
| **供应商管理** | 供应商准入、评估、淘汰 | 检查供应商档案 |
| **价格管理** | 定价机制、比价要求 | 价格合理性分析 |
| **验收管理** | 验收人、验收标准 | 检查验收记录 |
| **付款管理** | 付款条件、付款审批 | 检查付款记录 |

**常见控制缺陷**：
- 职责未分离（采购兼验收）
- 无供应商评估机制
- 无比价要求
- 验收流于形式

### 库存管理制度分析

**关注要点**：

| 要点 | 分析内容 | 转化为程序 |
|------|----------|------------|
| **盘点要求** | 盘点频率、盘点方法 | 检查盘点报告 |
| **出入库管理** | 出入库审批、台账 | 检查出入库单 |
| **存货保管** | 保管责任人、存放条件 | 现场检查 |
| **呆滞料管理** | 呆滞料识别、处理 | 分析账龄 |

**常见控制缺陷**：
- 盘点不定期
- 出入库无审批
- 无呆滞料处理机制

### 质量管理制度分析

**关注要点**：

| 要点 | 分析内容 | 转化为程序 |
|------|----------|------------|
| **检验标准** | 检验项目、检验方法 | 检查检验记录 |
| **不合格品处理** | 隔离、评审、处置 | 检查不合格品报告 |
| **质量追溯** | 批次管理、追溯记录 | 抽样追溯 |
| **客户投诉** | 投诉处理流程 | 检查投诉记录 |

**常见控制缺陷**：
- 不合格品未隔离
- 无质量追溯
- 投诉处理不及时

## 文档分析工作流程

> **v2.0 更新**：目前已采用**双通道提取**机制——规则型（关键词匹配）+ 流程型（流程重建），两者合并去重后输出完整控制点清单。

```
读取制度文档
       ↓
   ┌──判断文档类型──┐
   │ 含流程描述     │ 纯条款/表单
   ↓               ↓
流程重建           │
(角色-动作-对象)    │
   ↓               │
节点控制分析        │
   ↓               ↓
          ├── 规则型提取（关键词+语义）
          │   类型：审批权限、职责分离、定期检查、文档记录
          ↓
      合并去重
          ↓
      整理控制点清单
          ↓
      识别风险点（含Handoff分析输出的control_gaps）
          ↓
      设计baseline审计程序模板
```

## 文档分析技巧

### 1. 关键词搜索法

在文档中搜索关键词，快速定位控制要求：

| 关键词 | 对应控制类型 |
|--------|--------------|
| 审批、批准、签字 | 审批权限控制 |
| 必须、应当、严禁 | 控制要求 |
| 禁止、不得 | 控制要求 |
| 定期、每月、每年 | 定期检查控制 |
| 职责分离、不相容 | 职责分离控制 |
| 记录、登记、台账 | 文档记录控制 |

### 2. 流程图分析法

如果文档包含流程图：
1. 追踪流程中的每个节点
2. 识别关键控制节点
3. 识别缺乏控制的环节
4. 识别职责分配

### 3. 对比分析法

将制度文档与实际操作对比：
- 询问员工实际操作
- 观察实际执行情况
- 识别制度与执行差异

### 4. 流程重建分析法（v2.0 新增）

**适用场景**：制度文本中控制信息嵌入在流程描述中，而非以"审批""分离"等控制语言显性声明。

**操作步骤**：
1. 从流程段落提取 `角色-动作-对象` 结构化三元组
2. 按业务时序排列为流程序列
3. 逐节点检视四维隐含控制（需授权？需分离？有频率？有记录？）
4. 分析节点间 Handoff（流转）的控制缺口
5. 与关键词法提取结果合并去重

**详细规范**：见 [process_reconstruction.md](./process_reconstruction.md)

## 常见制度缺陷

### 1. 制度缺失

**表现**：某业务活动无相应制度

**风险**：操作无规范，容易出错或舞弊

**审计建议**：建议建立相关制度

### 2. 制度过时

**表现**：制度未随业务变化更新

**风险**：制度不适用，执行困难

**审计建议**：建议更新制度

### 3. 制度冲突

**表现**：不同制度对同一事项规定不同

**风险**：执行混乱

**审计建议**：建议统一制度

### 4. 制度不可操作

**表现**：制度要求过于笼统或理想化

**风险**：执行流于形式

**审计建议**：建议细化制度

## 制度分析检查清单

分析企业制度时，检查以下内容：

- [ ] 制度是否明确了审批权限
- [ ] 制度是否规定了职责分离
- [ ] 制度是否要求定期检查
- [ ] 制度是否要求文档记录
- [ ] 制度是否规定了异常处理
- [ ] 制度是否明确了问责机制
- [ ] 制度是否与实际操作一致
- [ ] 制度是否存在漏洞或缺陷
