# 跨文件交叉验证规则

## 概述

本文档定义了document-organizer在批量分析多份制度文件时的交叉验证规则，确保不因单文件分析而误判"缺失控制"。

## 核心原则

**制度体系是一个整体，不能孤立评价单份文件。**

## 验证规则

### 规则1：业务领域覆盖检查

**目标**：确保每个业务领域至少有一份制度文件覆盖。

**执行步骤**：
1. 提取所有制度文件的目录/章节标题
2. 建立"业务领域-文件"映射表
3. 对每个业务领域，检查是否有控制点覆盖
4. 只有所有文件都扫描完毕且控制点为0时，才判定为"缺失"

**映射表模板**：

| 业务领域 | 覆盖文件 | 控制点数量 | 验证状态 |
|---------|---------|-----------|---------|
| 采购申请 | 采购管理制度 §2 | 3 | ✅ 已覆盖 |
| 验收 | 仓储管理制度 §3、质量管理制度 §4 | 5 | ✅ 已覆盖 |
| 呆滞料管理 | 无 | 0 | ⚠️ 待确认 |

### 规则2：引用关系追踪

**目标**：识别制度间的引用关系，确保被引用文件中的控制点被正确关联。

**识别模式**：

| 引用模式 | 示例 | 处理方式 |
|---------|------|---------|
| 明确引用 | "按照《XX制度》第X章执行" | 读取被引用文件，关联控制点 |
| 隐含引用 | "验收按相关规定执行" | 标记"引用不明确"，建议用户确认 |
| 交叉引用 | A制度引用B制度，B制度引用C制度 | 建立引用链，追踪到最终控制点 |

**引用追踪模板**：

```
引用源：采购管理制度 §6.2
引用目标：仓储管理制度 第3章
控制点关联：
  - CP-015（验收职责）→ 关联到采购管理业务领域
  - CP-016（验收标准）→ 关联到采购管理业务领域
验证状态：✅ 跨文件覆盖
```

### 规则3：冲突检测

**目标**：发现不同制度对同一事项的不一致规定。

**检测维度**：

| 维度 | 检测方法 | 示例 |
|------|---------|------|
| 职责归属 | 同一事项在不同制度中规定不同部门负责 | 采购制度说仓储部验收，仓储制度说质检部验收 |
| 审批权限 | 同一事项在不同制度中规定不同审批层级 | 采购制度说副总审批，财务制度说总经理审批 |
| 时间要求 | 同一事项在不同制度中规定不同时间要求 | 质量制度说每月检查，内控制度说每季度检查 |
| 金额阈值 | 同一事项在不同制度中规定不同金额标准 | 采购制度说5万需审批，费用制度说3万需审批 |

**冲突处理模板**：

```json
{
  "id": "CF-001",
  "description": "验收职责归属不一致",
  "doc_a": {
    "name": "采购管理制度",
    "section": "第4.1条",
    "rule": "仓储部负责验收",
    "version": "v2.1"
  },
  "doc_b": {
    "name": "仓储管理制度",
    "section": "第2.3条",
    "rule": "质检部负责验收",
    "version": "v1.3"
  },
  "risk": "执行部门无所适从，可能导致验收真空",
  "recommendation": "统一验收职责归属，修订相关制度"
}
```

### 规则4：缺失判定条件

**只有在以下条件全部满足时，才判定为"制度缺失"：**

1. ✅ 所有相关制度文件已分析完毕（无"引用待追踪"项）
2. ✅ 该业务领域在所有文件中控制点数量为0
3. ✅ 没有跨文件引用指向该领域
4. ✅ 行业基准认为该领域应有控制（参考industry_benchmarks.md）

**否则，verification_status 标记为：**

| 条件不满足项 | verification_status | 说明 |
|-------------|---------------------|------|
| 还有文件未分析 | `引用待追踪` | 等所有文件分析完成后再判定 |
| B文件有控制点 | `跨文件覆盖` | 标注来源文件和控制点ID |
| 行业基准不要求 | `待确认` | 提示用户确认是否需要该控制 |
| 不确定 | `待确认` | 需要用户确认 |

### 规则5：版本差异处理

**目标**：当同一制度存在多个版本时，正确识别哪个版本是当前有效的。

**处理步骤**：
1. 识别所有版本（通过文件名、内容中的版本号/日期）
2. 确认最新版本（日期最新或版本号最大）
3. 以最新版本为主要分析对象
4. 对比旧版本，生成差异报告
5. 在JSON输出中标注 `previous_versions` 和 `version_status`

## 验证输出

### 交叉验证摘要

```markdown
## 跨文件交叉验证摘要

### 业务领域覆盖
- 已覆盖：8个业务领域
- 待确认：2个业务领域（呆滞料管理、模具报废）
- 未覆盖：0个业务领域

### 引用关系
- 明确引用：5处
- 隐含引用：2处（需用户确认）
- 跨文件控制点关联：12个

### 冲突检测
- 发现冲突：1处（验收职责归属）
- 建议：修订采购管理制度或仓储管理制度，统一验收职责

### 缺失判定
- 已确认缺失：0个
- 待确认缺失：2个（呆滞料管理、模具报废）
```
