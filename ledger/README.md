# 桌子格式（正式格子，v1.2）

一张桌子只记一件事，比如冲压车间废料多了。
旧房间一个没动，这叠纸是新加的。

## 格子

* 左边三格，固定不变：确定的毛病、怀疑偷骗（标红）、说不清的信号。
* 右边贴证据，每条必须写谁给的、啥时候给的，等级照实标（A/B/C/D/E），能对上证据柜里的槽位号就写上，对不上写文件名也行。
* 写入口硬度门：红格（怀疑偷骗）新增必须先有 A/E 级硬证据，否则当场拒收（exit 2）；顺序是先贴证据再上桌。改字（set-slot）不管，门卫事后照扫。
* 抽屉三张表：问话表、检查表、报告表——每张记"在哪、什么状态"，不装内容。
* 打勾纸三句：证据够了吗、制度看全了吗、红格看了吗。

## 东西是怎么上桌的（直接写，不再收料）

各房间查出来的东西**不会自己飞上桌**，由各房间结论直写（A6 收料/搬家已删除）：

```bash
python ledger/ledger.py add-line 桌子.json --slot 说不清的信号 --text "结论" --room 看制度 --ref D-001 --status pending
python ledger/ledger.py add-task 桌子.json --title "新假设" --room 检查单 --ref R-010
```

落格对照（完整对照表见 `ledger.schema.json` 的「落格规则」，SKILL 下判断时查）：

| 来源 | 去哪格 |
|------|--------|
| 看制度 · 控制缺口 `已确认` | 确定的毛病 |
| 看制度 · 控制缺口 `待确认`、风险点、设计观察 `pending`、待查项、制度空白、说不清的举报 | 说不清的信号 |
| 看制度 · 制度冲突 | 确定的毛病（两份制度对不上，本身就是事实） |
| 检查单 · 无户口新假设 | 任务板（待查），查实转事实行 |
| 检查单 · 制度类风险（来源标注里的编号在制度分析里找得到） | **不上桌**——同一件事制度分析那条已经在桌上了，再上就摆两行（2026-09-14 定） |
| 执行取证 · 查实结论 | 确定的毛病 / 怀疑偷骗（红格须 A/E，无则拒收）+ 对单号 |
| 问题单里的证据条 | 右边证据 |
| 设计观察（current-audit.json 标了 `design_observations_consumed=true`，即已消化进审计程序） | **整个房间不上桌**（消化了再挂回来，会把已变成问题单的事摆两行）——2026-09-14 定 |
| 问题单 `待补充`、设计观察 `verified`/`rejected`、控制缺口 `跨文件覆盖` | **不上桌**（最后一条：别的制度里有，不算缺失） |

**直接写不盖旧字**：一次命令只动一处；同一编号重复立任务会被拒收；
任务查实先结任务再上桌，查否标作废。

`import`/`sweep` 已删除（A6）。老项目自带稳定副本，照常能跑，不受影响；

## 抽屉怎么填

```bash
python ledger/ledger.py set-drawer 桌子.json --name 检查表 \
    --path internal-audit-workspace/audit-programs/程序_v1.md --status 执行中
```

路径写相对项目根目录的即可（`check.py --workspace` 会核对路径是否存在）。

## 证据缺失怎么办（宪法#9）

证据拿不到**不是终点**。停在"证据不足，等待补充"是违规——必须把"证据为什么不存在"
本身当成一件要查的事，写三个可能方向：

```bash
python ledger/ledger.py add-gap 桌子.json --finding F-2026-003 --missing "绩效评分原始记录"
```

## 部署约定

* `ledger/` 跟 `_shared/` 一个待遇：setup-project 建项目时链接或拷贝，update-project 升级时同步。
* 5个零件已进 phase_gate 白名单（全阶段可用），已在 CLAUDE.md 注册，穷举检查认得它们。
* 桌子文件放 `internal-audit-workspace/audit-table/`，由 project-init 建项目时开第一张。
  **绝不能放 `<项目根>/ledger/`**——那是工具目录（指向总库的链接），放那里会把项目数据写进总库。

## 新旧对照

* 左边三格 ← 以前散在检查单、问题单里的怀疑，现在收拢到一处。
* 右边证据 ← 证据柜（`_evidence_catalog.json`）的槽位，槽位号、文件名、谁给的、哪天，原样抄过来。
* 下面来源 ← 以前 finding 里谁、什么时间、从哪来的那行字。
* 红格 ← 以前舞弊标记，现在单独一格标红。
* 抽屉 ← 以前三个房间吐的三张表格。

## 房间分工（一家管一处）

| 房间 | 往桌上写什么 | 用哪条命令 |
|------|-------------|-----------|
| 看制度 | 控制缺口 / 风险点 / 制度冲突 / 设计观察 | `add-line`（直写） |
| 问话 | 风险线索（进设计观察）+ 证据记录 | `add-line` + 证据用 `add-evidence` |
| 检查单 | 新假设先落任务板（待查，有户口的只挂引用不上新行）；程序本体归抽屉·检查表 | `add-task`/`close-task`、`set-drawer` |
| 执行取证 | 查实结论进格、证据上右边；证据拿不到的记缺口 | `close-task` + `add-line`、`add-gap` |
| 吵架 | 改结论 | `set-slot`（落盘记流水） |
| 报告 | 只读 | `audit_table.py`（报告前闸机，不写） |

## 检查工具（都不写桌子）

| 工具 | 什么时候跑 | 拦不拦 |
|------|-----------|--------|
| `check.py` | 日常 | 会拦（三格没写完、证据缺来源、舞弊高风险缺硬证据）；老版本桌子只提醒 |
| `checklist.py` | 想看进度 | 不拦，只出六句话看板 |
| `audit_table.py` | 报告签字前 | 会拦（单缺位、鬼号、红格没对单号） |
| `export.py` | 要一张签字存档的表 | 不拦，出三页总览 |
