# 资深审计员直觉推理引擎（Veteran Auditor Intuition Engine）

## 概述

本文档为 `audit-execution-assistant` 提供默会知识推理框架。

**核心洞察**：经验丰富的审计员能感知到"这个数据组合不对劲"，却很难完整表达为规则。本框架将这种感知结构化，使AI能够模拟资深审计员的直觉判断。

**Polanyi原理**："我们能做的多于我们能说的。"

---

## 执行时机与触发条件

**按风险等级分级执行**，避免token浪费：

| 风险等级 | 执行模块 | 说明 |
|---------|---------|------|
| 🔴 高风险 | 模块1+2+3+4（全部） | 必须运行完整直觉引擎 |
| 🟡 中风险 | 模块1（星座检测）+ 模块2（反直觉红旗） | 运行核心检测 |
| 🟢 低风险 | 跳过直觉引擎 | 直接生成finding |

## 模块1：异常星座检测（Anomaly Constellation）

### 核心原理

单个异常往往有无害解释。**多个异常同时出现时，这不是巧合。**

### 检查方法

将当前已发现的异常进行组合分析，识别以下经典星座模式：

### 星座1：幽灵供应商星座

| 构成要素 | 检测条件 |
|---------|---------|
| 要素A | 供应商注册地址 = 员工居住小区附近或同一地址 |
| 要素B | 付款账号在系统中近期修改 |
| 要素C | 采购金额始终在审批权限阈值下方 |

**触发条件**：3个要素中至少命中2个
**置信度**：命中2个=中，命中3个=高
**排除条件**：供应商为政府指定唯一供应商，或员工已离职超过2年

### 星座2：合谋星座

| 构成要素 | 检测条件 |
|---------|---------|
| 要素A | 两个不相容岗位的操作时间戳极度接近（分钟级别） |
| 要素B | 涉及的业务金额集中在特定时间段（月末/年末） |
| 要素C | 该业务类型的历史异常率突然在特定人员接手后上升 |

**触发条件**：3个要素中至少命中2个
**置信度**：命中2个=中，命中3个=高
**排除条件**：业务量本身在月末/年末集中（如季节性行业）

### 星座3：隐藏操作星座（制造业特有）

| 构成要素 | 检测条件 |
|---------|---------|
| 要素A | 废品率或损耗率持续优于行业水平（不合理的"好"） |
| 要素B | 对应期间存货账面金额正常 |
| 要素C | 废料处置记录不完整或过于简洁 |

**触发条件**：3个要素中至少命中2个
**置信度**：命中2个=中，命中3个=高
**排除条件**：本月引入了新工艺或新设备，经技术部门确认废品率确实下降

### 星座4：数字操控星座

| 构成要素 | 检测条件 |
|---------|---------|
| 要素A | 大量业务金额刚好低于审批阈值（如X.99万元，阈值X万元） |
| 要素B | 这种分布在统计上异常集中（Benford定律检验） |
| 要素C | 同一审批人对应的这类业务比例显著高于其他人 |

**触发条件**：3个要素中至少命中2个
**置信度**：命中2个=中，命中3个=高
**排除条件**：合同金额由客户招标确定，非供应商自主定价

### 星座5：存货异常星座（存货审计特有）

| 构成要素 | 检测条件 |
|---------|---------|
| 要素A | 某类存货周转天数显著高于历史水平或同行业 |
| 要素B | 该类存货的采购频率未相应降低 |
| 要素C | 该类存货的仓储费用或损耗率上升 |

**触发条件**：3个要素中至少命中2个
**置信度**：命中2个=中，命中3个=高
**排除条件**：公司为应对预期价格上涨而战略性囤货，有管理层决策记录

### 识别到星座后的处理

1. **不直接得出"存在舞弊"结论**
2. 在 finding 中标注："发现以下异常星座，建议深化调查"
3. 列出具体构成要素和置信度
4. 建议下一步调查方向

## 模块2：反直觉红旗清单（Counter-Intuitive Red Flags）

以下情况表面看起来"好"，但经验丰富的审计员知道要特别关注：

| 表面现象                | 反直觉解读                  | 建议追查方向                        |
| ------------------- | ---------------------- | ----------------------------- |
| 盘点差异为零或极小           | 自然状态下不可能完美，可能数据被修饰     | 核查盘点记录的修改历史                   |
| 某供应商的合同执行100%合规     | 可能只在核查时合规，或关系太近无人敢查    | 检查该供应商的历史问题记录                 |
| 某岗位人员从不请假/休假        | 正常轮换是内控要求，长期不休可能有人怕被接管 | 核查关键岗位强制休假执行情况                |
| 领导非常配合、提前准备好所有资料    | 资料准备得"太好"可能经过筛选        | 要求系统直接导出，不接受手工整理版本            |
| 废品率/损耗率持续优于行业水平     | 可能实际废品没有入账，或被挪作他用      | 交叉验证生产投料量与产出量                 |
| 控制测试100%通过          | 抽样到的样本可能经过选择           | 要求随机抽样，不接受被审计方"协助选取"          |
| **系统导出数据和手工台账完全一致** | **手工台账可能是根据系统数据反向编制的** | **要求审计人员现场监督系统导出，不接受事后提供的文件** |
| 某类业务在审计期间突然大幅减少     | 可能在审计前刻意清理了异常记录        | 对比审计期间与审计前6个月的数据              |

## 模块3：时间维度直觉（Temporal Pattern Recognition）

经验丰富的审计员对时间模式有敏感直觉：

### 月末/季末集中效应

- 检查异常记录是否集中在月末最后3天
- 检查审批时间戳是否集中在下班后或节假日
- 检查金额调整是否在结账前大量发生

### 新人效应

- 新管理人员上任后3-6个月，历史舞弊最容易暴露（新人打破原有平衡）
- 同时也是新舞弊最容易建立的时期（内控尚未稳定）

### 审计前效应

- 对比审计期内 vs 审计前6个月的异常频率
- 若审计期内数据"异常干净"，本身就是一个信号

### 节假日效应

- 长假前最后一个工作日的异常操作频率通常是平时的3-5倍（利用监管真空期）
- 春节、国庆等长假后的第一周，异常记录可能集中暴露

### 系统切换效应

- ERP/MES系统上线前后3个月是舞弊高发期（数据迁移混乱，旧系统停用，新系统未稳）
- 系统升级期间的权限变更需要特别关注

## 模块4：二阶思维（Second-Order Thinking）

每个 finding 写完后，问以下问题：

### 问题1：掩盖检验
> "如果我是一个想掩盖这件事的人，我会怎么做？这些痕迹是否已经在数据中消除？"

### 问题2：受益者检验
> "这个发现的直接负责人是谁？但谁才是真正的受益者？两者是同一人吗？"

### 问题3：连锁失效检验
> "如果这个控制失效是蓄意的而不是疏忽，哪些其他控制也可能同时失效？"

### 问题4：时机检验
> "现有证据能解释'这件事为什么发生'，但能解释'为什么选择在这个时间点发生'吗？"

### 处理规则

| 回答情况 | 处理方式 |
|---------|---------|
| 4个问题均有合理解释 | 正常生成 finding |
| 1-2个问题答案令人不安 | 生成 finding，标注"建议扩大调查范围" |
| 3个及以上问题答案令人不安 | 标记"疑似舞弊"，升级风险等级为高，建议启动舞弊调查程序 |
