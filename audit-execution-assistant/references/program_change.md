# 程序变更管理

> 当用户选择"替代"、"新增"或"删除"时，进入本流程。
> 变更仅在当前审计程序文件中操作，不需要调 internal-audit-program-generator。

## 变更类型确认

| 用户输入 | 类型 | AI 响应 |
|---------|------|---------|
| `替代` | 修改现有程序 | "A-003 原计划的证据无法获取，请描述实际情况，我来设计替代方法。" |
| `新增` | 补充新程序 | "请描述发现的新风险或新线索，我先生成草稿程序供你确认。" |
| `删除` | 移除不适用程序 | "确认要删除 [程序编号]？请说明原因。" |

## 替代流程（证据拿不到，换方法）

```
用户选"替代"
  → AI 确认无法获取的证据项
  → 用户说明实际情况（如"SAP该模块未上线，只有纸质单据"）
  → AI 设计替代方案（在同一程序定义中追加"替代方法"行）
  → 用户确认
  → 修改 audit-programs/ 中的程序：
      在原程序行下方追加一行"替代方法：[新方法]"，标注"【替代】"和日期
  → 记录变更到程序文件末尾的"执行中程序变更记录"
  → 回到 Step 2（按替代方法接收证据）
```

**替代方法格式示例**：
```
| R18 | 直拨外协无财务对账 | A-003：直拨外协入库控制测试 | SAP MM入库记录 | 最近30天，抽取20笔 |
|     |                     | 【替代】直拨外协纸质单据抽查 | 纸质出库单+采购员签字 | 最近3个月全部纸质单据 |
```

## 新增流程（发现新风险，补充程序）

```
用户选"新增"
  → AI 收集：风险名称、风险描述、证据线索、对应轨道
  → AI 生成新程序草稿（含程序目标、测试步骤、取数来源、量化标准）
  → 用户确认或修改
  → 分配新程序编号：
      轨道A-F：当前最大编号+1（如从 A-027 → A-028）
      跨轨道/新线索：X-001, X-002...（X 表示"执行中新增"）
  → 写入 audit-programs/ 对应轨道章节下，标注"【执行中新增】"和日期
  → 记录变更到程序文件末尾的"执行中程序变更记录"
  → 更新当前程序的执行进度（总数+1）
  → 回到 Step 1，显示新程序的操作界面
```

## 删除流程（程序不适用）

```
用户选"删除"
  → AI 确认原因
  → 在 audit-programs/ 中标注"【已删除-原因：XXX】"，保留原行内容
  → 记录变更到程序文件末尾的"执行中程序变更记录"
  → 更新执行进度（跳过程序+1，总程序数不变）
  → 自动进入下一程序
```

## 执行中程序变更记录

每次变更操作后，在审计程序文件的末尾维护一个结构化变更记录表：

```markdown
## 附录：执行中程序变更记录

| 日期 | 程序编号 | 类型 | 变更原因 | 变更内容摘要 |
|------|---------|------|---------|-------------|
| 2026-05-07 | A-003 | 替代 | SAP该模块未上线 | 追加纸质单据抽查替代 |
| 2026-05-07 | X-001 | 新增 | 发现废料报价单未签字 | 新增报价单形式合规性检查 |
| 2026-05-07 | B-004 | 删除 | 已由C-003覆盖 | 删除冗余程序 |
```

**硬规则**：
- 每次变更必须同时更新此记录表，禁止跳过
- "替代"和"删除"必须保留原始程序内容，不得直接删除或覆盖
- "新增"的 X 编号按顺序递增（X-001, X-002...）
- 所有新增程序在后续执行摘要和报告中纳入统计
