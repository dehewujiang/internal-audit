# IIA/ACFE 专业标准框架

## 概述

本文档为 `audit-execution-assistant` 提供审计发现（Finding）质量标准和职业怀疑要求。

**核心原则**：每个审计发现必须经得起审计委员会审查、外部审计师复核、以及被审计方挑战。

---

## Finding 质量：IIA CCEER 结构

每个审计发现必须完整包含五个要素（CCEER），缺一不可。这是 IIA Standard 2410 的强制要求。

| 要素 | 英文 | 说明 | 质量标准 | 常见错误 |
|------|------|------|---------|---------|
| **标准** | Criteria | 应该是什么？ | 引用具体制度条款/行业标准/法规条文，不得用"应当""通常"等模糊表述 | ❌ "公司应当加强审批管理" |
| **状况** | Condition | 实际是什么？ | 可量化：数量、金额、比例、时间范围 | ❌ "部分单据缺少审批" |
| **原因** | Cause | 为什么会这样？ | 必须到达控制层面（设计缺陷 or 执行缺陷），不停在表象 | ❌ "操作人员疏忽" |
| **影响** | Effect | 产生了什么后果？ | 量化实际损失或估算潜在损失 | ❌ "可能造成损失" |
| **建议** | Recommendation | 如何改进？ | 针对原因，具体可执行，有时间节点和验收标准 | ❌ "建议加强管理" |

### CCEER 合格示例

```
标准：《外购件仓库管理规定》(CHCY-QC-SG-016) 第4.1.4条规定：
     "紧急放行的物资须经质量部负责人批准，并做好标识和记录。"

状况：抽查2024年1月至2025年3月共112笔紧急放行记录，
     其中15笔（占13.4%）未经质量部负责人审批，
     由质检员自行决定放行，涉及金额68.5万元。
     其中最大单笔12.8万元，审批人为质检员李XX。

原因：紧急放行审批流程在SAP系统中未设置强制校验节点，
     系统允许质检员跳过质量部负责人审批直接完成放行操作；
     同时制度未明确紧急放行的金额分级审批标准，
     形成控制设计层面的内控空白。

影响：15笔未经审批的紧急放行中，
     9笔后续检验不合格（不合格率60%），
     其中3批次已发往主机厂客户，存在客户投诉和索赔风险；
     9批次已流入生产环节，可能影响产品质量。

建议：①在SAP系统中设置紧急放行强制审批流程，
     质量部负责人审批节点不可跳过，完成时限：30天；
     ②修订《外购件仓库管理规定》，明确紧急放行金额分级审批标准
     （5万元以下质量主管审批，5万元以上质量部负责人审批），
     完成时限：30天；
     ③对已发往客户的3批次不合格品启动召回程序，
     完成时限：15天。
```

### CCEER 不合格示例（禁止）

```
❌ 标准：公司应当加强紧急放行管理
❌ 状况：部分紧急放行未经审批
❌ 原因：操作人员未遵守制度
❌ 影响：可能造成质量风险
❌ 建议：建议加强紧急放行管理
```

## 职业怀疑（Professional Skepticism）

基于 ISA 240 和 ACFE 职业怀疑标准，每个 finding 生成后，必须执行以下自检：

### 自检问题清单

1. **最简解释检验**：这个解释是最简单合理的解释，还是有更深层的原因？
2. **独立验证检验**：被审计方提供的解释是否经过了独立验证？
3. **舞弊掩盖检验**：如果这是舞弊的掩盖，证据会有什么不同？
4. **替代解释检验**：是否存在其他合理的解释？我是否排除了它们？
5. **证据充分性检验**：如果这个 finding 被提交给审计委员会，每个要素是否有可验证的证据支撑？被审计方能否用一份文件推翻我的结论？

### 处理规则

| 自检结果 | 处理方式 |
|---------|---------|
| 5个问题均通过 | 正常生成 finding |
| 1-2个问题存疑 | 生成 finding，标注"部分问题待进一步核实" |
| 3个及以上问题存疑 | 不生成 finding，标记"需要补充证据"，列出需补充的证据清单 |

## 证据充分性标准（IIA Standard 2310/2320）

### 充分性（Sufficiency）

| 证据类型 | 最低样本量 | 时间覆盖 |
|---------|-----------|---------|
| 控制测试 | ≥25笔（一般控制）或 ≥60笔（关键控制） | 覆盖整个审计期间 |
| 实质性测试 | 全量分析或统计抽样 | 覆盖整个审计期间 |
| 舞弊调查 | 全量 + 穿透核查 | 覆盖异常发生全周期 |

### 可靠性等级

| 等级 | 类型 | 可靠性 | 示例 |
|------|------|--------|------|
| A | 系统直接导出 | 高 | SAP导出的采购订单清单（含系统时间戳） |
| B | 系统截图 | 中高 | 系统审批流程截图 |
| C | 手工记录 | 中 | 手工填写的盘点表 |
| D | 口头描述 | 低 | 员工口述流程 |
| E | 第三方证据 | 高 | 供应商对账单、银行流水 |

**规则**：
- 高风险 finding：至少需要 A 级或 B 级证据
- 中风险 finding：B 级或 C 级证据可接受
- 低风险 finding：C 级或 D 级证据可接受
- 舞弊相关 finding：必须有 A 级证据 + 第三方证据（E级）交叉验证

## 管理层回复要求（IIA Standard 2440）

每个 finding 必须包含管理层回复字段：

```json
"management_response": {
  "response": "被审计方回复内容",
  "response_date": "回复日期",
  "management_action_plan": "管理层整改计划",
  "target_completion_date": "计划完成日期",
  "auditor_assessment": "充分|不充分|需补充证据"
}
```

**审计师评估标准**：
- **充分**：回复针对根因，有具体整改措施和时间节点
- **不充分**：回复停留在表象，或整改措施不可执行
- **需补充证据**：回复缺乏支撑材料，或时间节点不合理
