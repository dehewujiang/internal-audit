# 根因分析方法论

## 概述

本文档为 `audit-execution-assistant` 提供 cause 字段的生成逻辑。

**核心原则**：禁止停在"操作人员未遵守制度"这一层。每个发现的根因必须追溯到控制设计层或控制环境层。

---

## 根因分析三层框架（映射COSO）

每个 finding 的 `cause` 字段必须追溯到以下三层之一，且必须到达层次1或层次2。

### 层次1：控制环境层（最深）

**COSO 映射**：控制环境（Control Environment）

**特征**：治理结构缺陷、管理层态度、激励机制扭曲、资源不足、企业文化问题

**典型表现**：
- 管理层KPI设计不合理（如仅考核产量不考核质量）
- 管理层对某类风险长期忽视
- 关键岗位长期缺编
- 企业文化容忍某类违规行为

**示例**：
> "管理层KPI仅考核产量不考核废品率，操作人员有系统性动机绕过质检流程以完成产量目标；同时废品率连续3个季度超标但管理层未采取纠正措施，形成容忍文化。"

### 层次2：控制设计层（中层）

**COSO 映射**：控制活动（Control Activities）

**特征**：制度本身有漏洞、职责设计不合理、缺少关键控制点、系统功能缺失

**典型表现**：
- 制度未规定关键控制环节
- 不相容职责未分离
- 系统未设置强制校验
- 审批权限设计不合理

**示例**：
> "废料处置制度（2023年版第6条）未要求独立监磅人员，全流程由单一操作员完成，形成设计层面的内控空白；同时地磅系统无操作日志留存功能，事后无法追溯异常操作。"

### 层次3：控制执行层（表层）

**COSO 映射**：监控（Monitoring Activities）

**特征**：制度存在但未被遵守——**若追溯到这里必须继续问"为什么没执行"**

**典型表现**：
- 日常检查频率降低
- 监督虚化
- 执行人员知道无人抽查
- 培训不到位导致操作不规范

**示例（不合格 - 停在表层）**：
> ❌ "操作人员未按规定进行双人验收。"

**示例（合格 - 追溯至层次2）**：
> ✅ "操作人员未按规定进行双人验收。经追溯：化学品仓库仅配置2名仓管员，轮班时无法满足双人操作的人员要求（层次2-资源设计缺陷）；同时近1年未对仓管员进行'五双'制度培训（层次2-培训机制缺失）。"

## 5-Why 分析法

生成 cause 字段时，至少问5次"为什么"，直到触达层次1或层次2。

### 示例：紧急放行未经审批

```
Q1: 为什么紧急放行未经审批？
A1: 质检员自行决定放行，未报质量部负责人审批。

Q2: 为什么质检员可以自行决定？
A2: SAP系统中紧急放行流程无强制校验节点，质检员可直接跳过审批。

Q3: 为什么系统无强制校验？
A3: 系统上线时未将紧急放行审批纳入工作流配置。

Q4: 为什么上线时未纳入？
A4: 需求评审阶段，业务部门未提出系统强制校验需求，IT部门按最小化需求开发。

Q5: 为什么业务部门未提出？
A5: 业务部门认为"制度规定了就行"，未意识到系统控制比制度约束更可靠。
```

**根因结论**（层次2-控制设计层）：
> "紧急放行审批流程在SAP系统中未设置强制校验节点，系统允许质检员跳过审批直接完成操作；需求评审阶段业务部门未提出系统控制需求，IT部门按最小化需求开发，形成控制设计层面的内控空白。"

**注意**：不要机械地"问5次"。有些 finding 3次就到根因，有些需要7次。标准是：**问到无法再追问为止，且必须触达层次1或层次2。**

**例外**：如果确实无法从层次3继续追溯（符合下面"根因终止条件"中允许停在 EXEC-01 的情形），须在 cause 字段中明确说明终止原因。

## 根因分类标签

每个 cause 字段应包含以下分类标签之一，便于后续统计分析：

| 标签 | 含义 | 对应层次 |
|------|------|---------|
| `ENV-01` | 治理结构缺陷 | 层次1 |
| `ENV-02` | 管理层态度/容忍文化 | 层次1 |
| `ENV-03` | 激励机制扭曲 | 层次1 |
| `ENV-04` | 资源不足/关键岗位缺编 | 层次1 |
| `DES-01` | 制度漏洞/缺少关键控制点 | 层次2 |
| `DES-02` | 职责设计不合理/不相容未分离 | 层次2 |
| `DES-03` | 系统功能缺失/无强制校验 | 层次2 |
| `DES-04` | 审批权限设计不合理 | 层次2 |
| `DES-05` | 培训机制缺失 | 层次2 |
| `EXEC-01` | 执行不到位（需继续追溯） | 层次3 |

## 根因终止条件（新增）

### 为什么需要终止条件

"必须追到层次1或层次2"是一个理想要求。现实中有部分发现确实止于纯执行问题——强行往上追会导致 LLM 编造虚假的"深层原因"，反而降低 finding 可信度。

**铁律**：宁停在 EXEC-01 并标注原因，也比虚构深层根因好。

### 允许停在 EXEC-01 的情形

| 情形 | 判定标准 | cause 字段写法要求 | 同时须在 finding 中标注 |
|------|---------|-------------------|----------------------|
| **纯形式合规问题** | 缺少签字、格式不合规等，不影响实质性控制目标，无经济损失 | 明确写："经5-Why追溯未发现更深层原因。该问题为孤立执行偏差，相关制度有明确规定，同级岗位同步执行率>95%，仅该笔/人例外。" | `cause_category: "EXEC-01"` + 在 `audit_team_notes.confidence_level` 标注"中" |
| **孤立执行偏差** | 单笔/单人违规，非系统性问题，无重复发生模式 | 同上，并补充"近6个月同类业务仅此一例，排除制度设计缺陷" | `cause_category: "EXEC-01"` + 说明排除范围 |
| **证据不足以支撑更深层推断** | 只有 D 级证据（口头/访谈），无法独立验证系统或制度层面的原因 | 写："证据不足（仅D级），无法进一步追溯。建议补充【具体证据类型】后再评估。根因结论当前仅为初步判断，置信度低。" | `cause_confidence: "low"` + `audit_team_notes.key_uncertainties` 中列出待补充证据 |

### 不允许停在 EXEC-01 的情形（仍须强制追溯）

| 情形 | 说明 |
|------|------|
| 高风险 finding，且 evidence 中有 A 级或 E 级证据 | 证据足以支撑更深层分析，停在 EXEC-01 等于懒政 |
| 同类问题在前一年审计中已被记录 | 已知的系统性问题，必须追到设计/环境层 |
| 5-Why 追问的前3步已经追溯到层级2 | 说明追溯链已经建立，继续完成即可 |

### 违反终止条件的后果

| 违规类型 | 发现机制 | 处理 |
|---------|---------|------|
| 停在 EXEC-01 但未标注 | validate-finding.py Step 6 检查 | 自动阻断 |
| 虚构深层根因（证据不足硬造） | Step 5 质量回溯检查 | 标记"质量待审"，退回修正 |
| 未标注 cause_confidence="low" | validate-finding.py Step 6 检查 | 自动阻断 |

## 根因质量自检

生成 cause 字段后，执行以下自检：

| 自检项 | 通过标准 | 不通过处理 |
|--------|---------|-----------|
| 是否停在"操作人员未遵守"？ | 否 | 检查是否符合终止条件，不符合则继续追溯 |
| 是否符合终止条件？ | 如果是 EXEC-01，必须有终止条件标注 | 补充终止原因说明 |
| 是否引用了具体制度条款？ | 是 | 补充制度引用 |
| 是否区分了设计缺陷和执行缺陷？ | 是 | 明确标注 |
| 是否考虑了系统因素？ | 是（如适用） | 补充系统分析 |
| 是否考虑了人为因素？ | 是 | 补充人为因素分析 |
| 证据等级是否支撑根因深度？ | 高风险 + D级证据 → 标注置信度低 | 降级或补充证据 |
