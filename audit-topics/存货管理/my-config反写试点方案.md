# my-config 反写试点方案（存货管理）

> 状态：草稿，待你确认后才进 skill
> 一句话：制度里有的 LLM 摘、访谈听来的 LLM 起草、你只点确认，不让你手填。

## 1. 为什么试点存货

- 存货有 8 份典型制度（topic.json 已登记），盘点、废料、呆滞这些在制度里一般写得最全，反写效果最明显
- 访谈最容易问出"实际不一样"（比如 VMI 到底哪天确认、称重是系统还是手工），正好验证"口说→验过"这条链
- 只动存货一个主题，不碰其他主题和全局文件

```
制度文档 ──分析完──→ 草稿A（制度摘的）──→ 你点确认 ──→ 进 my-config
访谈问卷 ──回填后──→ 草稿B（听来的） ──→ 你点确认 ──→ 进 my-config（先标待验）
草稿B ──拿到证据──→ 转正（已验证）
```

## 3. 回答你的问题：访谈回来什么时候反写、谁动手

**答案：系统自动起草，你只点确认。不让你手填。**

分两步走，你只在第二步出现：

**第 1 步（系统自动，不用你管）：**
什么时候：你把填好的访谈 Excel 发回来，我处理完的当下就出草稿
做什么：按现在 interview skill 的分流去向，配置类的自动写成 my-config 草稿行，格式如下

```markdown
- 过磅地点与责任人: 1号地磅，物流门，过磅员张XX【口说待验·仓管员李某 2026-XX-XX】
```

**第 2 步（你点确认，30 秒）：**
你只回三句话中的一句：

- "确认" → 草稿转正（还是标待验，等证据来了再去验）
- "改成XXX" → 我按你说的改
- "这条不要" → 删掉

为什么不让你手填：你手填要翻聊天记录、翻 Excel，还容易抄错人名字和日期。系统从回填结果里直接摘，人名日期不会错。

**访谈验证什么时候做（C 路）：**
不是回填当下，是拿到下面任一证据时才转"已验证"：

- 第二个人说了同样的话（跨人对上）
- 拿到了单子/截图/报表路径（话和纸对上）
- 进现场执行程序时抽查对上

转正格式：

```markdown
- 过磅地点与责任人: 1号地磅，物流门【已验证·访谈李某+王某+DRL-03地磅记录】
```

## 4. A 路什么时候反写（制度那一路）

什么时候：document-organizer 跑完 8 份存货制度、你看完分析报告说"可以"之后
做什么：LLM 按第 2 节的 A 类字段出草稿，每行带出处，例如：

```markdown
- 盘点频率: 每月抽盘+每季全盘【制度摘·《NPM001成品仓库管理标准》§X.X】
```

你只点确认。制度里没写的，LLM 不许编，直接标"制度没写，转访谈"，自动进下一轮访谈问卷。

## 5. 三种状态（一眼看懂）

| 标记 | 意思 | 能不能给审计程序用 |
|---|---|---|
| 【制度摘·xxx】 | 制度原文里有的 | 能用，出报告可引用 |
| 【口说待验·谁+日期】 | 访谈听来的，还没验 | 程序里能用，但要加"需现场验证" |
| 【已验证·依据】 | 对上了（跨人/单据/抽查） | 能用，出报告可引用 |

## 6. 老规矩怎么改（topic-wizard 那条"禁止自动改"）

原来"禁止自动改 my-config"是怕 LLM 瞎编。现在改成：

- LLM 可以写草稿，但**没出处的不写**
- 你手改过的地方，LLM 不许覆盖，只许在旁边提示"制度里是这么写的，要不要对一下"
- 每次反写只增量加行，不重写整个文件

## 7. 试点步骤（存货，只做这几步）

1. 跑完 8 份存货制度分析 → 出 A 类草稿 → 你确认
2. 按"制度没写"清单生成访谈问卷 → 你去问 → 发回来
3. 系统自动出 B 类草稿 → 你确认（确认/改/不要三选一）
4. DRL 证据回来 → 对上的转"已验证"
5. 你验收：抽 3 行，能说出每行的出处，就算过

## 8. 回滚

- 你说"回退"，直接拿备份覆盖回来
