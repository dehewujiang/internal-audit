# 实战援助与逐轮教练：三个 prompt 骨架

三个能力共用原则：以下骨架里的占位符按实况填，不许凭空编造 finding 细节。
findings 细节一律从真实 finding JSON / 桌子 JSON 读入。

---

## 一、驳论预判（发话之前）

**触发**：用户说"我要这样回复/这样质问……"并求预判，或处于沟通会准备阶段。

**骨架**：

```
# 任务：预判被审计方反驳
审计师即将发送以下回应，请预判被审计方可能提出的 2-3 个反驳论点。

[被审计方画像]: {画像四项+四变量，见 auditee_profile.md}
[角色卡]: {所选 role_xxx.md 的狡辩模式}
[当前发现]: {finding 的状况描述（condition）}
[对话历史]: {最近6轮，每轮截断200字}
[审计师的草稿回应]:
"{用户草稿原文}"

## 输出要求
JSON 数组，每条包含：
- counterArgument: 被审计方可能说的反驳内容（1-2 句）
- suggestedResponse: 建议审计师的应对方式（1-2 句）

只输出 JSON 数组，不要其他文字。
```

---

## 二、逐轮点评（整场演练）

**触发**：攻防演练模式进行中，每轮自动附。

**形式**：被审计人回应之后，另起一行输出 `---`，最后一行以 `[点评]` 开头，
给一句不超过 30 字的沟通策略建议。

**示例**：

```
（被审计方的具体回应文字，1-5句话）

---
[点评] 对方在回避核心问题，建议直接追问具体证据
```

**规则**：点评只谈对策，不评价用户情绪；演练推进规则（反驳有据→推进、
站不住脚→原地/倒退、新证据→大幅推进、人身攻击→对抗升级倒退）
照 SKILL.md 主体执行，本文件不改推进规则。

---

## 三、回复分析（实战援助，真实沟通会进行中）

**触发**：用户说"贴原话/分析这句话/这话怎么破"，把**真实**被审计方的
原话贴进来。此时切换到实战模式：不再扮演，只分析。

**骨架**：

```
# 任务：被审计人回复分析
被审计单位给出了最新的回复，请分析其话术背后的逻辑漏洞、
转移话题的尝试或潜在的阻挠意图。

[背景]: {finding 的状况描述}
[对话历史]: {已有回合}
[被审计人最新回复]:
"{用户粘贴的原话，一字不改}"

分析重点：
1. 对方是否在回避核心问题？→ 指出回避的是哪个问题
2. 是否存在逻辑矛盾？→ 与此前证词/证据的冲突点
3. 是否在转移话题？→ 从哪个话题转移到哪个话题
4. 建议审计师下一句该怎么问？（具体的追问话术草稿，可直接使用）
```

**实战模式三条纪律**：
- 只分析和建议，不替用户定论——定性是审计师的职责
- 追问草稿必须锚定"对方原话里的具体字眼"，禁止泛泛的"请提供更多证据"
- 分析结果按需可以做记录（存 debates/ 存档，格式同攻防演练），方便沟通会
  结束后回写 finding 的沟通记录
