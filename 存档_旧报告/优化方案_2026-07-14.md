# 内部审计AI系统 — 优化方案

> 编制日期：2026-07-14  
> 依据：全面审计报告（15项发现）+ Excel导出列结构诊断（7项发现）  
> 状态：待用户确认

---

## 一、方案目标

解决"Excel导出与MD格式不一致"的根因——**三套列定义打架**，并系统治理全面审计发现的22项问题（4高/11中/7低）。

## 二、设计原则

1. **单一真相源**：列结构只在 `program_templates.json` 一处定义，SKILL.md、output_template.md、validate-program.py、program_generator.py 全部引用它，不各自定义
2. **三层分离**：风险溯源(①) + 程序设计(②) + 执行记录(③)，各层职责清晰
3. **校验兜底**：validate-program.py 真正校验列头一致性，不一致则阻断——让"硬规则"不再是空头支票
4. **不向后兼容旧格式**：用户将删除旧格式MD重新生成，新脚本只支持新列结构，不写降级路径——减少代码复杂度

## 三、统一列结构定义

### 三层框架

| 层 | 职责 | 谁填 | MD输出 | Excel输出 |
|----|------|------|:------:|:---------:|

**轨道特有列说明**（第②层差异化）：
- A有"抽样方法"——控制测试结论依赖样本量
- B有"舞弊手法"+"量化阈值"——舞弊测试需明确手法和异常阈值
- C有"量化阈值"——系统数据测试需明确异常特征
- D有"为什么这家公司更需要关注"——边界探测的核心要求（SKILL.md 3.4节硬性要求）
- E有"量化指标"——效率测试需量化（周转天数/人效等）
- F有"检查对象"——合规测试需明确查什么证书/记录

**特殊表处理**：轨道E的"E6效率损失金额估算"表（损失维度|估算方法|估算金额|置信度）不属于程序表，导出脚本单独识别并跳过，或在Excel单独一个Sheet。

## 五、第一批详细设计（列结构统一）

### 5.1 program_templates.json 重写

每个轨道的 `columns` 改为三层结构，新增 `layer` 标注：

```json
{
  "A": {
    "columns": [
      {"name": "风险编号", "width": 12, "layer": "risk"},
      {"name": "风险名称", "width": 20, "layer": "risk"},
      {"name": "来源标注", "width": 20, "layer": "risk"},
      {"name": "程序编号", "width": 12, "layer": "design"},
      {"name": "测试程序", "width": 45, "layer": "design"},
      {"name": "抽样方法", "width": 15, "layer": "design"},
      {"name": "取证方式", "width": 20, "layer": "design"},
      {"name": "判定标准", "width": 25, "layer": "design"},
      {"name": "测试结果", "width": 15, "layer": "execution"},
      {"name": "执行人", "width": 12, "layer": "execution"},
      {"name": "执行日期", "width": 12, "layer": "execution"}
    ]
  }
}
```

- `layer: risk` = ①风险溯源（MD和Excel都输出）
- `layer: design` = ②程序设计（MD和Excel都输出）
- `layer: execution` = ③执行记录（仅Excel输出，留空）

导出脚本根据 `layer` 决定：MD只输出risk+design列，Excel输出全部三层。

## 七、风险与回退

| 风险 | 应对 |
|------|------|
| 列结构改动影响已有项目 | 用户将删除旧格式MD重新生成，无需兼容——新脚本只支持新列结构 |
| output_template.md重写后AI生成行为变化 | 第一批改完后，用武汉长源的主题重新生成一次程序，对比新旧MD差异，确认AI遵循新模板 |
| validate-program.py新增校验阻断程序 | 用户删除旧MD重新生成，校验直接block，无需观察期 |
| VERSION.json记录显示v2.0三层曾回退 | 本次回退的原因可能是"只改了一两个文件没改全"——本次4个文件一起改，且增加校验兜底 |

**回退方案**：每批改动前 `bump-version.py --commit` 打版本标签。出问题时 `update-project.ps1` 回退到上一版本（已有备份轮转机制）。
