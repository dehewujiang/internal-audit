#### B2：修复 data_executor.py Windows 超时（P1-14）

- **文件**：`_shared/scripts/data_executor.py`
- **改动**：替换 signal.SIGALRM 方案为 `threading.Timer` + `subprocess` 方案：
  ```python
  import threading
  timer = threading.Timer(30, lambda: (_ for _ in ()).throw(TimeoutError("超时")))
  timer.start()
  try:
      exec(code, namespace)
  finally:
      timer.cancel()
  ```
  更稳健的方案：将代码执行放到子进程中，父进程用 `subprocess.run(timeout=30)` 控制。

#### B3：加固 data_executor.py 沙箱（P1-15）

- **文件**：`_shared/scripts/data_executor.py`
- **改动**：移除 `'__import__': __import__`，改为白名单 import 机制：
  ```python
  def _safe_import(name, *args, **kwargs):
      allowed = {'pandas', 'numpy', 'math', 'datetime', 'collections', 'itertools', 'json', 'csv'}
      top_level = name.split('.')[0]
      if top_level not in allowed:
          raise ImportError(f"不允许导入模块: {name}")
      return __import__(name, *args, **kwargs)
  safe_builtins['__import__'] = _safe_import
  ```

## 六、风险分析

| 风险 | 概率 | 影响 | 应对措施 |
|------|:---:|:---:|------|
| validate-finding.py 重写后与现有 finding 不兼容 | 中 | 已有 finding 无法通过新校验 | 保留旧 schema 校验为 `--legacy` 模式，新 finding 默认用新 schema |
| constitution #10 检查脚本可能因 topic.json 格式差异崩溃 | 中 | 某些主题无法检查 | 脚本中做 defensive 读取：reference_framework 不存在时输出警告而非崩溃 |
| data_executor.py 子进程超时方案在 Windows 上笨重 | 中 | 超时响应不够精确 | 优先 threading.Timer 方案，子进程作为备选 |
| 修改 CLIPON-project.md 约束数导致依赖方混淆 | 低 | 用户误以为删除了约束 | 选择方案：将额外 4 条合并回 constitution.md 而非降数 |
| 整改过程中新的并发修改 | 低 | 合并冲突 | 修改前先 git pull，修改后立即 commit 并 push |
